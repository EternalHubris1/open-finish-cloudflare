# Open Finish Design Lab

Treat Open Finish as a Personal Operating System for long-term mastery. Build a distinctive language by synthesizing evidence, never by importing another product's look.

## Start with memory

Read `../../../design-lab/DESIGN_BIBLE.md`, `../../../design-lab/DECISIONS.md`, and `../../../design-lab/PROCESS.md`. Read [workflow.md](references/workflow.md) for artifact states and review gates. Treat anything not marked approved as an experiment.

## Route the task

- Use `ask-nodumb` when the product intention, person, context, model, or expensive assumption is unclear.
- Use `nodumb` before a large redesign, system-wide change, or costly implementation direction.
- Use `system-feedback` for actions and loading, empty, error, success, undo, and edge states.
- Use browser inspection for responsive and interactive visual QA.
- Use `visualize` for an in-conversation comparison, mockup, diagram, or exploratory chart when seeing or manipulating it improves the decision.
- Use `imagegen` only when original raster imagery or illustration is genuinely part of the art direction; prefer code-native UI and established vector systems otherwise.

## Work in evidence order

For major decisions: frame the tension → research best-in-class principles → compare distinct approaches → explain trade-offs → recommend one direction → prototype → review → iterate → document approval.

Do not jump from a reference to implementation. Do not offer equal options without a position. Prototype only enough to test the riskiest choice, using realistic content and all relevant states.

Keep Dashboard responsible for current state, momentum, focus, and direction. Keep History responsible for analytics, trends, breakdowns, and long-term insights.

## Preserve design memory

Move a decision into the Design Bible only after explicit approval. Convert a recurring review comment into a general rule only when its broader applicability is confirmed. When language evolves, add a decision entry and mark the old rule superseded; never erase rationale or silently redesign from scratch.

End major design work with a clear recommendation, validation result, approval status, and the exact memory documents changed.
